# Промпт для coding-агента: VoiceFlowWin

> **Исторический документ.** Это исходное техническое задание, по которому
> создавался первый прототип с Vosk. Текущая реализация использует
> sherpa-onnx/Zipformer; актуальное устройство описано в `ARCHITECTURE.md`.

Разработай полноценную Windows-утилиту для голосового набора текста в реальном времени, по поведению максимально близкую к системной диктовке macOS.

Рабочее название проекта: **VoiceFlowWin**.

Не ограничивайся анализом, архитектурой, описанием или псевдокодом. Создай рабочий проект, реализуй приложение, настрой автоматическую сборку и выпуск через GitHub Actions, подготовь установщик, механизм обновлений, тесты и документацию.

---

## 1. Цель проекта

Пользователь устанавливает приложение на Windows, назначает удобную клавишу или сочетание клавиш для вызова голосового набора, устанавливает курсор в любое текстовое поле и запускает диктовку.

Во время речи текст должен появляться непосредственно в активном текстовом поле в реальном времени.

После завершения речевого сегмента локальная модель Whisper должна повторно распознать этот сегмент, исправить ошибки потокового результата Vosk и безопасно заменить только текст текущего сегмента.

Приложение должно работать:

- на Windows 10 x64;
- на Windows 11 x64;
- без обязательного подключения к интернету для распознавания;
- с русским и английским языками;
- в браузерах, мессенджерах, редакторах и других приложениях;
- независимо от текущей раскладки при непосредственной вставке кириллицы или латиницы.

Обработка аудио и текста должна выполняться локально.

## 2. Ключевые пользовательские сценарии

### 2.1. Запуск голосового набора

Пользователь назначает в настройках:

- одну клавишу;
- либо сочетание клавиш.

Эта клавиша или сочетание запускает голосовой набор глобально, независимо от активного приложения.

Поддержать два режима:

1. **Toggle**
   - первое нажатие запускает диктовку;
   - повторное нажатие назначенной клавиши или сочетания завершает диктовку.

2. **Push-to-talk**
   - диктовка идёт, пока пользователь удерживает назначенную клавишу или сочетание;
   - отпускание завершает ввод и запускает финальную обработку текущего сегмента.

### 2.2. Обязательное выключение по Escape

Клавиша `Esc` всегда должна останавливать активный голосовой набор.

Правила:

- `Esc` работает независимо от назначенной основной горячей клавиши;
- `Esc` работает в режимах Toggle и Push-to-talk;
- при нажатии `Esc` захват микрофона прекращается;
- текущий аудиосегмент корректно завершается;
- приложение не должно зависать в состоянии активной записи;
- пользователь может выбрать в настройках, нужно ли финализировать уже распознанную фразу либо полностью отменить текущий незавершённый сегмент;
- по умолчанию `Esc` завершает диктовку и сохраняет уже распознанный текст;
- повторно назначить `Esc` на другую функцию нельзя;
- основная назначаемая горячая клавиша не может быть только `Esc`.

Если `Esc` используется приложением для остановки диктовки, во время активного голосового набора это нажатие не должно передаваться активному приложению, если из-за этого может закрыться окно, диалог или меню.

Вне активного голосового набора приложение не должно перехватывать `Esc`.

## 3. Технологический стек

Используй:

- C#;
- .NET 8;
- WPF;
- NAudio или прямой WASAPI для захвата микрофона;
- Vosk API для потокового распознавания;
- `whisper.cpp` для финального распознавания;
- локальный VAD;
- P/Invoke к Windows API;
- Microsoft UI Automation там, где она повышает надёжность;
- Microsoft.Extensions.DependencyInjection;
- Microsoft.Extensions.Logging;
- JSON для пользовательских настроек.

Целевая архитектура: `win-x64`. Дополнительную `win-arm64` добавляй только если это не усложняет основной выпуск.

CPU-режим обязателен. GPU-ускорение можно добавить как дополнительный backend, но приложение должно полноценно работать без дискретной видеокарты.

Whisper должен подключаться как библиотека через устойчивый native wrapper или собственный минимальный P/Invoke-слой. Не запускай отдельный консольный процесс для каждой фразы.

## 4. Гибридное распознавание Vosk + Whisper

Используй две модели с разными задачами.

### Vosk

Vosk обеспечивает:

- низкую задержку;
- потоковое распознавание;
- промежуточные гипотезы;
- появление текста во время речи.

### Whisper

Whisper обеспечивает:

- финальную перепроверку завершённого речевого сегмента;
- более точное распознавание;
- исправление форм слов;
- пунктуацию;
- сохранение английских терминов внутри русской речи;
- корректировку только последнего сегмента.

### Общий принцип

```text
Микрофон
→ WASAPI/NAudio
→ PCM mono 16 bit 16 kHz
→ кольцевой аудиобуфер
→ Vosk
→ потоковый текст
→ VAD
→ завершённый аудиосегмент
→ Whisper
→ согласование Vosk и Whisper
→ безопасное обновление текста текущего сегмента
```

Vosk и Whisper должны получать один и тот же исходный аудиосегмент.

---

## 5. Потоковый ввод через Vosk

Vosk должен работать во время активной диктовки и возвращать промежуточные результаты с минимальной задержкой.

Требования:

- обновление промежуточной гипотезы ориентировочно каждые 100–300 мс;
- распознавание не блокирует UI;
- аудиозахват не блокирует UI;
- обработка выполняется в фоновых потоках;
- поддерживается CancellationToken;
- native-ресурсы корректно освобождаются;
- приложение не вставляет каждую гипотезу целиком;
- нельзя допускать повторного появления уже введённых слов.

Создай компонент `StablePrefixProcessor`.

Он должен хранить:

- предыдущие гипотезы;
- текущую гипотезу;
- подтверждённый префикс;
- изменяемый хвост;
- количество повторных совпадений токена;
- время последнего изменения токена;
- количество символов, уже вставленных приложением.

Слово можно считать стабильным, если оно:

- совпало в нескольких последовательных гипотезах;
- либо не менялось заданное время;
- не относится к последним нестабильным словам фразы.

Настройки по умолчанию:

- 2–3 последовательных совпадения;
- 500–800 мс без изменения;
- последние 1–3 слова остаются изменяемым хвостом.

## 6. Режимы живого отображения текста

### Безопасный потоковый режим

Используется по умолчанию.

- в активное приложение вводятся только стабильные слова;
- изменяемый хвост показывается в overlay;
- риск лишних Backspace минимален;
- финальная версия фразы корректируется после Whisper.

### Максимально живой режим

- в активное приложение вводится и стабильная часть, и изменяемый хвост;
- при изменении гипотезы приложение удаляет только собственный предыдущий хвост;
- затем вводит новый хвост;
- этот режим должен иметь предупреждение о меньшей совместимости;
- нельзя удалять текст после пользовательского вмешательства.

---

## 7. Сегментация речи и VAD

Используй локальный VAD: Silero VAD, WebRTC VAD либо другой подходящий локальный движок.

Добавь настройки:

- чувствительность;
- минимальная длительность речи;
- длительность паузы для окончания сегмента;
- pre-roll;
- post-roll;
- максимальная длительность одного сегмента.

Значения по умолчанию:

- завершение сегмента после паузы 700–900 мс;
- небольшой pre-roll, чтобы не терялось начало слова;
- небольшой post-roll;
- максимальная длительность сегмента 20–30 секунд.

Сегмент завершается:

- после достаточной паузы;
- после повторного нажатия основной горячей клавиши в Toggle-режиме;
- после отпускания клавиши в Push-to-talk;
- после нажатия `Esc`;
- после достижения максимальной длительности.

Следующий аудиосегмент можно записывать, пока предыдущий обрабатывается Whisper, но Whisper-задачи должны выполняться через контролируемую очередь без одновременного запуска нескольких тяжёлых распознаваний.

---

## 8. Финальное распознавание через Whisper

Whisper получает только завершённый аудиосегмент.

Требования:

- мультиязычная модель;
- русский и английский;
- режим перевода отключён;
- результат остаётся на языке оригинальной речи;
- автоматическая пунктуация;
- настраиваемая модель;
- выбор числа CPU-потоков;
- ограничение параллелизма;
- отмена задачи при завершении приложения;
- безопасное освобождение native-ресурсов.

Не передавай в Whisper весь разговор с начала сессии.

Можно передавать ограниченный текстовый контекст из последних подтверждённых слов, если API это поддерживает и это не приводит к повторению предыдущего текста.

## 9. Язык набора

Не усложняй систему несколькими одновременно работающими распознавателями без доказанной необходимости.

Основное правило:

- текущая русская раскладка → основной язык распознавания русский;
- текущая английская раскладка → основной язык распознавания английский.

Определяй раскладку активного приложения через Windows API:

- GetForegroundWindow;
- GetWindowThreadProcessId;
- GetKeyboardLayout;
- WM_INPUTLANGCHANGE, где это уместно.

При смене раскладки:

- текущий уже начатый сегмент можно завершить на ранее выбранном языке;
- новый сегмент должен использовать новый язык;
- уже введённый текст не меняется;
- диктовка не должна аварийно завершаться.

Добавь настройки:

- «Язык по раскладке» — по умолчанию;
- «Всегда русский»;
- «Всегда английский»;
- «Автоопределение Whisper».

### Английские слова при русской раскладке

При русской раскладке пользователь может произнести отдельное английское слово, название продукта, технологии или короткий английский термин.

Ожидаемое поведение:

- «открой GitHub» → `Открой GitHub`;
- «добавь JSON файл» → `Добавь JSON-файл`;
- «проект на dot net» → `Проект на .NET`;
- «используй Whisper» → `Используй Whisper`;
- «создай pull request» → `Создай pull request`;
- «запусти Docker Compose» → `Запусти Docker Compose`.

Не создавай сложную одновременную схему из русского и английского Vosk на первом этапе.

Используй простой порядок:

1. Основной потоковый Vosk работает на языке текущей раскладки.
2. Пользовательский словарь исправляет известные английские термины в промежуточном тексте.
3. Мультиязычный Whisper выполняет финальную обработку сегмента и сохраняет английские слова латиницей.
4. После Whisper применяется пользовательский словарь и правила регистра.
5. Если Whisper уверенно распознал английское слово, не транслитерируй его кириллицей и не переводи.

## 11. Назначение горячей клавиши

Пользователь должен назначать клавишу или сочетание клавиш непосредственно в интерфейсе настроек.

Сценарий:

1. Пользователь открывает поле «Клавиша вызова голосового набора».
2. Нажимает кнопку «Назначить».
3. Приложение переходит в режим захвата.
4. Пользователь нажимает одну клавишу либо сочетание.
5. Приложение показывает человекочитаемое название.
6. Пользователь сохраняет настройку.
7. Новая комбинация начинает работать без перезапуска приложения.

Поддержать:

- одиночные функциональные клавиши;
- Ctrl;
- Alt;
- Shift;
- Win;
- комбинации модификаторов;
- F1–F24;
- дополнительные клавиши клавиатуры, если Windows их поддерживает;
- боковые кнопки мыши как дополнительную возможность, если реализация надёжна.

Горячая клавиша должна:

- работать глобально;
- работать независимо от раскладки;
- храниться как virtual key code и модификаторы, а не как символ;
- корректно восстанавливаться после перезапуска;
- не вводить случайный символ в активное поле;
- работать в Toggle и Push-to-talk;
- проверяться на конфликт.

По умолчанию: `Ctrl + Alt + Space`.

Добавь кнопки:

- «Назначить»;
- «Проверить»;
- «Сбросить»;
- «Вернуть по умолчанию».

При конфликте:

- не сохраняй сочетание молча;
- покажи понятное сообщение;
- предложи выбрать другую клавишу.

Для Toggle используй RegisterHotKey, если сочетание поддерживается.

Для Push-to-talk и одиночных клавиш используй безопасный low-level keyboard hook.

`Esc` всегда остаётся отдельной системной клавишей остановки голосового набора и не является пользовательской настройкой.

## 12. Согласование Vosk и Whisper

Создай компонент `HybridTranscriptionCoordinator`.

Для каждого сегмента храни:

- SegmentId;
- исходный аудиобуфер;
- язык сегмента;
- раскладку на момент начала;
- промежуточный текст Vosk;
- стабильный текст Vosk;
- изменяемый хвост Vosk;
- текст, реально вставленный приложением;
- число вставленных символов;
- текст Whisper;
- состояние сегмента;
- активное окно;
- focused control;
- время начала;
- время окончания;
- признак вмешательства пользователя.

Состояния:

- Recording;
- Streaming;
- AwaitingFinalization;
- WhisperProcessing;
- Finalized;
- Frozen;
- Cancelled;
- Failed.

После получения Whisper-результата:

1. Нормализуй текст.
2. Обработай пробелы.
3. Обработай русскую и английскую пунктуацию.
4. Примени пользовательский словарь.
5. Сравни результат с текстом текущего SegmentId.
6. Замени только текст текущего сегмента.
7. Не изменяй предыдущие сегменты.
8. Не ищи фразу по всему документу обычным строковым поиском.
9. Используй внутренний учёт вставленных символов.
10. Не заменяй текст после вмешательства пользователя.

Для сравнения используй:

- longest common prefix;
- longest common suffix;
- word-level diff;
- character-level diff;
- edit distance;
- учёт реально вставленных символов.

## 13. Защита пользовательского текста

Создай компонент `InputInterventionMonitor`.

Он должен отслеживать:

- смену активного окна;
- смену focused control;
- движение курсора;
- пользовательский ввод с клавиатуры;
- клики мышью;
- выделение текста;
- удаление текста;
- вставку из буфера;
- Undo;
- смену документа;
- изменение содержимого, не инициированное VoiceFlowWin.

Если пользователь вмешался в текст после начала сегмента:

- сегмент переводится в `Frozen`;
- автоматическая замена Whisper запрещается;
- уже введённый текст остаётся;
- финальный результат показывается в overlay;
- доступны кнопки «Заменить вручную», «Скопировать», «Оставить как есть».

Никогда не отправляй Backspace вслепую.

Удаление собственного хвоста допускается только если:

- active window не изменилось;
- focused control не изменился;
- пользователь не вмешивался;
- приложение точно знает длину собственного хвоста;
- хвост относится к текущему SegmentId.

## 14. Вставка текста

Создай `TextInjectionService`.

Основной способ:

- Unicode SendInput;
- корректная кириллица и латиница;
- независимость от текущей раскладки.

Резервный способ:

- временная вставка через буфер обмена;
- Ctrl + V;
- восстановление предыдущего содержимого.

При работе с буфером обмена:

- по возможности сохраняй все форматы;
- не уничтожай пользовательские данные;
- обрабатывай занятый буфер;
- выполняй несколько попыток;
- не восстанавливай старое содержимое, если пользователь сам успел изменить буфер;
- используй безопасную задержку.

Добавь режимы:

- SendInput;
- Clipboard;
- Auto fallback;
- Compatibility mode.

Учти Unicode, surrogate pairs, переносы строк, Emoji и различие между длиной строки .NET и количеством визуальных текстовых элементов.

## 28. Автоматическая проверка обновлений

Создай `UpdateService`.

Проверять обновления:

1. При каждом запуске приложения.
2. Затем каждые 4 часа непрерывной работы.

Проверка при запуске выполняется асинхронно и не должна задерживать запуск приложения или голосового набора.

Источник:

- `update-manifest.json`;
- при необходимости GitHub Releases API как fallback.

Предпочтительно использовать manifest.

Пример:

```json
{
  "version": "1.4.2",
  "minimumSupportedVersion": "1.0.0",
  "releaseDate": "2026-08-05T10:00:00Z",
  "installerUrl": "https://example/VoiceFlowWin-Setup-x64-1.4.2.exe",
  "portableUrl": "https://example/VoiceFlowWin-Portable-x64-1.4.2.zip",
  "sha256": "HEX_SHA256",
  "size": 12345678,
  "mandatory": false,
  "releaseNotesUrl": "https://example/release-notes"
}
```

UpdateService должен:

- сравнивать SemVer;
- не выполнять downgrade;
- не предлагать текущую версию;
- учитывать Stable/Beta;
- не предлагать prerelease на Stable;
- иметь таймаут;
- корректно обрабатывать отсутствие сети;
- не показывать навязчивую ошибку при отсутствии интернета;
- сохранять техническую ошибку в лог.

## 29. Автоматическая загрузка обновления

После обнаружения новой версии:

1. Установщик автоматически скачивается в фоне.
2. Отображается прогресс.
3. Проверяется размер.
4. Проверяется SHA-256.
5. При наличии цифровой подписи проверяется подпись.
6. Только после проверки обновление считается готовым.
7. Пользователю показывается «Обновить сейчас» или «Позже».

Хранить файлы в `%LocalAppData%\VoiceFlowWin\Updates`.

Загрузка:

- сначала во временный файл `.download`;
- после полной загрузки и проверки переименовать в `.exe`;
- поддержать HTTP Range, если возможно;
- удалить устаревшие пакеты.

Непроверенный файл никогда не запускается.

## 30. Выбор «Обновить сейчас»

При выборе:

1. Не начинать установку во время активной диктовки.
2. Предложить корректно завершить или отменить сегмент.
3. Сохранить настройки.
4. Освободить модели.
5. Запустить отдельный updater или проверенный installer.
6. Передать PID приложения.
7. Закрыть основной процесс.
8. Дождаться завершения процесса.
9. Обновить приложение.
10. Перезапустить VoiceFlowWin.
11. При ошибке сохранить рабочую текущую версию.

Обновление должно быть максимально атомарным.

## 31. Выбор «Позже»

Если пользователь нажал «Позже»:

- уже скачанный файл не удаляется;
- повторное сообщение не показывается немедленно;
- приложение продолжает работу;
- при следующей плановой проверке через 4 часа предложение показывается снова;
- при перезапуске предложение показывается после проверки при запуске;
- перед повторным предложением проверяется SHA-256;
- если вышла более новая версия, предыдущий пакет удаляется и скачивается новый.

Для обычного обновления кнопка «Больше не напоминать» не нужна.

Допускается скрытая расширенная настройка пропуска конкретной необязательной версии.

Для обязательного обновления:

- только «Обновить сейчас» либо «Закрыть приложение»;
- пропуск запрещён.

## 37. Критерии приёмки

Проект готов, когда:

1. Запускается на Windows 10 и 11 x64.
2. Работает из трея.
3. Пользователь назначает клавишу или сочетание.
4. Назначенная клавиша запускает диктовку глобально.
5. `Esc` всегда останавливает активную диктовку.
6. Русский текст появляется во время речи.
7. Английский текст появляется при английской раскладке.
8. Английские термины внутри русской речи сохраняются латиницей после финализации.
9. Vosk не создаёт повторов.
10. Whisper исправляет текущую фразу.
11. Предыдущий текст не переписывается.
12. Пользовательский текст не удаляется.
13. После движения курсора замена блокируется.
14. Кириллица вводится независимо от раскладки.
15. Распознавание работает без интернета.
16. Аудио не сохраняется.
17. Есть Model Manager.
18. Есть portable-сборка.
19. Есть установщик EXE.
20. Release собирается GitHub Actions.
21. GitHub Release создаётся автоматически.
22. Обновления проверяются при каждом запуске.
23. Обновления проверяются раз в 4 часа.
24. Обновление автоматически скачивается.
25. После загрузки есть «Обновить сейчас» и «Позже».
26. После «Позже» напоминание повторяется при следующей проверке.
27. Настройки и модели сохраняются при обновлении.
28. Есть тесты.
29. Нет критических native memory leaks.
30. Приложение работает непрерывно не менее часа.
